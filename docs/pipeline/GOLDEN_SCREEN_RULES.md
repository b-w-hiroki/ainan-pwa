# AINAN Golden Screen Rules

## 参照画と証跡を混同しない

- **承認方向の参照**: docs/concept-art/canonical/ のモック。ここにある構図・視認性・操作主役を意図として保存する。
- **実装の証跡**: CIのartifacts/e2e/*.png。コードのそのcommitで実際に描画された画面。
- **自動guard**: scripts/visual-screenshot-guard.mjs。390×844、欠損サイズ、ファイル重複などを検出。ピクセル完全一致やUI重なりを自動判定しているわけではない。

golden-screens.jsonは「毎CIで撮影する画面名と意図」の台帳であり、CI画像を承認済みgolden masterへ勝手に昇格させない。

## 制作フローv2の受入基準

[ART_DIRECTION_BIBLE.md](ART_DIRECTION_BIBLE.md) と [art-direction-contract.json](art-direction-contract.json) の既存承認素材を品質の起点にする。特に海面の質感、人物のシルエット、青・金UI、魚の大きさが現行より低下するなら置換しない。

新しい素材の審査は **承認方向のモック／現行mainの実画面／候補ブランチの実画面** を同じ390×844で比較。別視点の画像生成例や圧縮された参考JPGだけで品質を決めない。画面を1枚生成しても独立素材・状態・操作連動がなければ未完了。

## 比較の順序

1. 390×844実キャプチャを取得する。PWAキャッシュ等の旧ビルドを流用しない。
2. 承認モックと同じ画角で配置、画面上下の優先順位、余白、背景/主役の比率を確認。
3. 文字・タップ対象・魚影・釣り糸・キャラ・CTAの重なり、クリッピングを確認。
4. キャストから釣果まで実操作を通し、フェーズ遷移時の旧レイヤー残留・入力二重発火を確認。
5. 実装の差異/妥協点をPRに記載。ユーザー承認が必要な方向転換は別途レビューする。
6. CI成功、スクショ目視、操作検証の3つが揃って完了。

### 重要な未検査領域

AIが作る静止画の完成度、実機iPhoneでのsafe-area/音声・PWA復帰、実タッチ遅延、10分以上の発熱・メモリはCIスクショ単体では判定できない。Issue #27のリリースゲートを飛ばさない。
