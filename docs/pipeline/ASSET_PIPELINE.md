# AINAN Asset Pipeline

## 原則

1枚絵をゲーム画面へ丸ごと貼り付けて量産しない。WORLD / PLAYER / FISH / UI / FX / TOWNの部品に分け、状態に応じて合成する。例外的な承認済み合成素材が既存実装にある場合は、置換を急がずassetManifestのowner・使い道を記録して段階的に整理する。

素材の「生成元」と「実際に描画される製品asset」は別物。GPT画像や参考モックから作った絵は、それだけで実装済みとはしない。

## 手順

### 1. 体験の狙いを固定

例: 「引っ張る → パワーが溜まる → 狙いへキャスト → 着水」の気持ちよさ。1タスクで改善する感情・操作・画面状態を1つ決める。

### 2. 正解モックとレイヤーを定義

390×844で構図を固定。位置、見切れ、文字の大きさ、中央の水面の可読性と操作対象を確認する。

- WORLD: 空 / 雲 / 遠景 / 陸 / 海 / 桟橋 / 灯台 / 漁場固有物
- PLAYER: 身体 / ポーズ / 竿 / ライン / 影 / 成功・失敗反応
- FISH: 魚影 / 寄り / HIT / バトル / ジャンプ / Result / 図鑑
- UI: 上部情報 / キャスト / リール操作 / テンション / GET / 町へ持ち帰る / もう一投
- FX: 水紋 / 水しぶき / 光 / カメラ / 魚の発光 / 大物演出
- TOWN: 町の成長レイヤー / 施設 / NPC / 市場・食堂の反応

### 3. Master → 状態差分

まずアジ×港の1ループをマスターにし、Cast→Retrieve→HIT→Battle→Result→Townの代表素材を揃える。次に色やサイズだけを乱数で変更するのではなく、タイ/ブリ/クエ等の動きや表情、漁場差分を追加する。

素材状態は asset-states.json に記録する。種別は次の3つ。
- asset: assetManifest内にreadyの実ファイルが存在する。
- procedural: 指定コードによる描画・アニメーションで、個別画像はない。
- planned: 未制作。完成済みとしてカウントしない。

例: アジの魚影は共通shadow素材、興味動作は実装コード、バトルとResultは専用魚素材、専用ジャンプフレームはplanned。

### 4. 生成・加工・由来の管理

- 生成ブリーフに画角、パレット、形、線、視点、光、縁の余白、透明領域、切り出し単位を含める。
- 背景・プレイヤー・竿・魚・UI・FXを独立ファイル化。重なり修正用の調整代を残す。
- UIの可変テキストは原則Phaserで描画（静的な承認済み装飾の文字は例外）。
- SVGは小さく安全に、写真調素材は圧縮したWebP/PNG。透過・ぼかし・余白・縁取りを小画面で確認。
- 生成元と正規化後の関係を docs/art-spec/GENERATED_ASSET_PROVENANCE.md に追記。元絵をローカルだけに残さない。利用可能な元ファイルは docs/art-spec/generated-source-images/ 等で出所を追えるようにする。
- 実装素材は fishing-game/assets/ に置き、assetManifest.jsへ登録し、scene preloadまで確認。
- 当該釣りフィールドの小部品は docs/art-spec/asset-definitions.json と整合させる。

### 5. コンテンツデータと結合

魚: fishId、habitat、rarity、size、retrieve、battle、resultなどの既存仕様に合わせる。釣り場: pointA/B/C、背景・水・魚候補・天候/時間帯。町: 釣果→施設/料理/図鑑との紐付け。ゲームデータは「新しい絵を追加したから」という理由で無断調整しない。

### 6. 配置と検証

表示ownerは visual-owners.json に従う。新UIを追加する前に旧ownerと入力hit areaを調査し、重複を残さない。390×844で端、キャラ、釣竿、魚影、ボタン、safe-areaを確認し、実操作の遷移まで通す。画像欠損・旧UI復帰は差し戻し。

## 大量追加時の単位

「50匹の画像」ではなく「1匹の釣り→町ループ」を先に完成させる。共通状態表の完了率を比較し、欠けている状態はplannedとして残す。50匹を一度に生成する前に1魚→3魚→10魚の順で横展開を検証する。
