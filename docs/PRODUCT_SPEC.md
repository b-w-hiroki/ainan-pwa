# AINAN 現行仕様書

更新日: 2026-10-20 / 対象: `main` の 1.0.0-rc.3 系。機能変更と同じPRで更新する生きた文書。

## 目的と対象

AINANは「釣り → 町おこし → 成長 → ボス」をつなぐブラウザゲーム/PWA。釣りの一操作ごとに魚の反応が読み取れ、スマートフォンの縦画面で一連の体験を完結できることを目指す。現行の基準画面は390×844。横画面の一部はQA専用試作であり、正式対応の仕様ではない。
短い縦画面の幅拡張はQA専用試作であり、Cast・Retrieve・食いつき待ちとHIT・Battle・Resultを幅基準で表示して下部操作を画面内へ移す。食いつき中は人物と魚影の背景を保ち、合図が出た時だけ下部に「今！タップ」を示す。CastとRetrieveの季節・時間・天候はヘッダー下の水面に表示する。Battleでは魚と水しぶきを人物より上の水面へ配置し、魚名・巻き進捗・暴れる予兆・操作案内とテンションゲージを読める大きさにする。Resultでは釣果の魚を人物の顔から右へ寄せ、表情と魚の両方を見せる。逃走時は助言と再挑戦・装備・港の操作ラベルを短画面でも読める大きさに保つ。ボス記録の通知は釣果の操作ボタンを隠さない。さらに低い320×480のQA画面ではBattleの人物・魚・進捗とResultの見出し・人物・カード・操作を画面内で分け、ボス通知も人物の顔を隠さない。同じQA切替ではTitle→Home→Map→Castの実タップ導線を維持し、320×480ではTitleの開始・遊び方、Homeの主要操作・フッター、Mapの釣り場ラベルを重ねない。320～375px幅の「遊び方」は基本ループと釣り操作を1列で示し、フッターを固定したまま上下にスクロールして全項目を読める。短い画面の釣り場詳細では準備情報・魚アイコン・釣りボタンを別段に配置する。正式な釣りループは引き続き390×844基準を全体縮小して表示する。QA専用の幅拡張中に画面サイズが変わっても、釣り糸は水面の目標へつながり、Battleの魚名とゲージの間に不要な文字を残さない。通常導線への適用には一連の遷移、入力、戻る導線、実機を含む確認が必要。

QA専用の短画面では、食いつき待ちとHITの合図中も画面左上の戻る操作からマップへ戻れる。見た目を切り替えた人物は巻き取りから食いつき待ちに移っても同じ大きさを保ち、糸は水面のルアーへつながり、距離表示も継続する。港の短画面では足元に岸壁を表示し、人物が水面に浮いて見えないようにする。巻き取りが進んでもルアーと魚影は水面に残り、下部操作に隠れない。320×480に上下の安全領域を設けた場合も、巻き取りと食いつき待ちの人物が釣り場名を隠さず、Battleの魚が人物を覆わないように配置する。ボス記録は１行にまとめて結果の操作ボタン下に表示し、人物の顔と操作を隠さない。

この文書は**現在のユーザー向け振る舞い**を定義する。目標モック、未採用の画像候補、検討中の設計は現行仕様と混同しない。実装との相違を見つけたら同じ変更PRでどちらを直すか決める。

## 体験の流れ

1. タイトルからホーム・町・マップを経て釣り場へ向かう。
2. 釣り場でキャストし、ルアーを巻きながら魚の反応を探る。
3. HIT後は魚の動きとテンションを見ながらバトルし、釣果または失敗を確認する。
4. 釣果と資源を町の活動・装備・次の釣りへつなげる。

画面遷移の実体は `fishing-game/js/main.js` と `fishing-game/js/scenes/`、釣りフェーズの実体は `fishing-game/js/scenes/GameScene.js` および `fishing-game/js/game/installFishingRuntime.js` にある。検証用URLの `qa=1` は通常のユーザー導線とは別扱い。

## 釣りの操作とフィードバック

| フェーズ | プレイヤーの行動 | 見える結果・終了条件 |
| --- | --- | --- |
| Cast | 方向と力を調整して投げる | 着水位置から巻き取りへ移る。投げ直し可能な状態は画面内で示す |
| Retrieve | 待つ・ちょい巻き・ゆっくり巻くを使い分ける | 残距離、ルアー、魚影や反応を表示。魚が食いつけばHITへ |
| HIT | 制限時間内に反応する | 成功すればバトル、逃せば失敗結果へ |
| Battle | テンションと魚の動きを見て巻く／待つ | 釣り上げまたは逃走へ遷移 |
| Result | 釣果を確認する | 町に持ち帰る、または再挑戦する |

同時に表示する主要操作は原則3つまでとし、押せる状態・反応・失敗理由が読み取れるようにする。魚影、ルアー、波紋、釣り糸、人物は互いの意味を隠さない。装飾や演出のために入力領域を失わせない。詳細な画面判定は [縦スライスQA](VERTICAL_SLICE_QA.md) と [UIコンポーネント仕様](ui-component-system-v1.md) を参照。

キャスト中の下部操作パネルは明るい半透明の面に「パワー」と表示した青いゲージと「投げる」ボタンを置き、水面を主役にする。長押しとリリースの案内をパネル内に表示し、従来の操作位置とタップ領域を維持する。

複数の魚がルアーへ反応しても、追尾する魚影と警戒表示・操作ヒントは同じ注目魚を示す。注目魚が離れたら古い反応ヒントを消し、次の操作を妨げない。初回の巻き取りガイドは保存領域が使えない端末でも釣りを継続できる。保存できなかった場合、次回起動時にガイドが再表示されることがある。

入力が受け付けられなかった場合は、成功した時の音・振動・キャストの揺れ・ルアーの水しぶきを出さない。エサ不足、着水直後の操作待ち、連続ちょい巻きのクールダウン中などは、実際の操作結果と演出を一致させる。

仕掛けを手元まで巻いた場合は回収演出を一度だけ再生し、回収中の巻き操作を受け付けず、完了後に投げ直しへ戻る。釣果やエサの追加消費は発生しない。

魚の食いつき待ちで手動で引き上げる場合やHITを逃した場合も、戻り演出・通知は一度だけとする。戻り待ちの連打で処理を重ねず、すでにバトルへ移った画面を遅れた戻り処理で上書きしない。

魚が誘引範囲にいない時の案内は、その食いつき待ち中だけ表示する。引き上げ・HIT・投げ直し・画面離脱後に古い案内を残さない。

## コンテンツと進行

現行の魚種・釣り場・嗜好・出現条件は `fishing-game/js/game/fish.js` と関連データが正本。現行魚種はアジ、タイ、バス、ブリ、サバ、イサキ、ヒラメ、カンパチ、クエの9種で、釣り場はA/B/Cの3地点。魚ごとの難易度や報酬値はデータと検証に合わせて変更し、この文書には変動しやすい数値を複製しない。

町・装備・釣果利用は現行の画面実装に従う。追加アイデアは [釣りと町のループ案](design/outgame-fishing-loop.md) にあるが、提案を実装済み仕様として扱わない。正式版への残作業は [固定バックログ](pipeline/REMAINING_BACKLOG_BASELINE_20261015.md)、最新の進捗・採否・依存関係はIssueを参照する。

横画面QA試作でResultから町へ魚を持ち帰った場合も、魚種別の釣果カードを横幅に合わせて表示し、町を見る／次の釣り場を選ぶ操作を残す。これは横画面の通常版対応や実機合格を意味しない。
小さい縦画面では釣果カードの操作を表示倍率に合わせて大きくし、港を見る／次の釣り場を選ぶタップ領域を実表示でも約44px以上に保つ。
町の施設発展ダイアログも、小さい縦画面では「発展／釣りへ」と「閉じる」を重ねず、実表示で押しやすい大きさにする。
タイトルの「遊び方」、マップと釣り画面の「戻る」、釣り場詳細の主要操作も、短い縦画面では実表示のタップ領域を約44px以上に保つ。釣り場詳細では説明を短い要約に切り替え、準備状態・ST・道具を読める文字サイズで示し、準備情報と魚アイコンが重ならない。
共通フッターの5タブは短い縦画面でもラベルを読める大きさに保ち、タブ同士の区別と操作を維持する。
クエ捕獲後の町ヘッダーでは、伝説バッジを画面左の見出し下に置き、短い縦画面でも所持ポイント・解放数と重ならない。

## 保存・配信・利用環境

- セーブはブラウザ内に保持する。現在の保存形式はversion 3で、インポート／エクスポート、整合性検証、ローテーションバックアップを備える。互換性を壊す変更には移行と復旧の検証を伴わせる。
- PWAとしてインストール可能。更新はプレイ中のフェーズを妨げず、安全な画面へ戻った時点で案内・適用する。
- 基準はスマートフォン縦画面390×844。小さい画面や高密度画面でも重要操作を使えることをQAで確認する。横画面の検証用プロトタイプは正式な全画面対応を意味しない。
- 物理iPhoneでの最終判定は [実機チェックリスト](qa/iphone-release-checklist.md) と [Issue #27](https://github.com/b-w-hiroki/ainan-pwa/issues/27) に残る。自動テストやエミュレーションで代用しない。

## 現行仕様と未完了の境界

港の背景・人物・小物の全面再構築は候補と本番採用を分ける。[Issue #216](https://github.com/b-w-hiroki/ainan-pwa/issues/216) とW01–W05の子Issueが最新の承認・ブロック状態の正本。旧グラフィックと保存データは、置換候補の独立レビューと移行検証が済むまで保持する。港固有の目標・構図は [港キャスト製品仕様](design/HARBOR_CAST_PRODUCT_SPEC.md) に記載されるが、目標仕様のすべてが現行画面へ実装済みという意味ではない。

正式リリースの完了判定には、コードと自動QAに加え、素材承認、通常導線での画面確認、物理iPhone QAをそれぞれ必要とする。
