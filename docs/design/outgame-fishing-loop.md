# AINAN アウトゲーム導線設計

Status: design only

Baseline: `main@06e25745bf9bb0c541ea206bdf226f25ac25475d`（PR #95 merge 後）

Scope: ホーム、釣り場、装備、成長、図鑑、釣果、所持品、次の目標、セーブ

## 1. 目的

アウトゲームを、次の一周が迷わず続く構造にする。

`出発前の選択 → 一投 / 釣行 → 釣果が残る → 次に狙う魚や装備を決める → 再出発`

最小構成では新しい通貨、ショップ、育成軸を追加しない。既存の価格、報酬、出現率、ST消費量も変更しない。新しい大画面も増やさず、既存の `HomeScene`、`MapScene`、`UpgradeScene`、`CollectionScene`、Result、`TownScene` の役割を整理する。

## 2. 現状の棚卸し

| 領域 | 既存実装 | 現状の主導線 | 整理すべき差 |
|---|---|---|---|
| ホーム | ST、pt、ジェム、釣果数、町成長、ミッション、デイリー、次の行動、装備の見た目を表示 | `getFishingJourney()` が状況別に Map / Town / Upgrade へ送る | 情報と入口が多く、「次の一投」の準備内容が一か所にまとまらない |
| 釣り場選択 | 港・湾・磯、解放条件、魚候補、未発見数、難度、環境、ボス、現在装備、餌数、STを表示 | 地点詳細の `この海で釣る -1ST` | 地点詳細から装備を確認できるが、その場で変更して同じ地点へ戻る文脈がない。魚アイコンは目標として選べない |
| 竿・餌・装備 | 竿 / 餌 / 素材タブ、所持数、購入・補充・装備、装備中表示 | フッターの「装備」から常設画面へ移動 | 装備変更後の行き先が常に独立しており、選んでいた釣り場や狙い魚へ戻らない |
| 見た目 | Home と Upgrade のキャラクターに竿・アクセサリを反映。Gameにも竿外観を反映 | 装備画面の CURRENT LOADOUT | 効果と見た目は存在する。出発確認で最終外観を短く再確認できない |
| 成長 | 竿Lv、アクセサリ、町施設Lv、町の賑わい、ボス、称号 | Workshop / Town / Profile / Challenge に分散 | 成長量は豊富だが、「次の一投に何が効くか」を出発前に絞って見せていない |
| 魚図鑑 | 9魚種、発見状態、釣果数、最大サイズ、BEST、釣れた場所・環境、ヒント、図鑑報酬 | Menu → 図鑑 → 魚詳細 | 魚詳細から「この魚を狙う」へ進めない。図鑑の知識が次の釣行計画に接続していない |
| 釣果 / 報酬 | 魚種、レア度、サイズ、スコア、初回・記録・レア報酬、素材、魚在庫、ボス判定を保存 | 成功Resultから町または同条件再投。町到着演出あり | 保存自体は即時だが、何が残ったかが複数画面に分散する。町到着後の次の一手が一貫しない |
| 所持品 | 竿、餌、素材、アクセサリ、魚在庫、食事効果を保持 | Upgrade / Workshop / 港の店に分散 | 「釣行に持ち込む物」と「町で使う物」が同じ優先度に見える |
| 次の目標 | 初回導線、次の海域解放、デイリー対象魚、ミッション、免許、ボス | Homeの複数カード | 主目標候補が競合する。釣行直前に採用した目標は保存されない |
| セーブ | 各値を `localStorage` へ即時保存。save version 3、チェックサム、3世代バックアップ、JSON入出力 | 起動時・非表示化時にバックアップ | 釣行中のphaseや選択中の地点・狙い魚は復帰しない。一部の `seen` / daily / pending キーはバックアップ対象外 |

既存の中心ロジックは以下を再利用できる。

- `getFishingPreparation(pointId)`: 地点、竿、餌、在庫、STとblockerを集約済み
- `getFishingJourney()`: 初回、町確認、成長、再挑戦の次行動を判定済み
- `getEquipment()` / `getInventory()`: 現在装備と所持数の正本
- `getCatches()` / `getFishRecord()`: 図鑑と釣果記録の正本
- `ResultUI` / `installTownCatchArrival`: 釣果から町までの演出とデータ受け渡し

## 3. 最小の体験構造

### 3.1 画面遷移

1. Homeで「次の釣行」を確認する。
2. Mapの地点詳細を「出発準備カード」として開く。
3. 地点、狙い魚、竿、餌、STを一枚で確認する。
4. 必要な場合だけ図鑑または装備へ寄り、完了後は同じカードへ戻る。
5. `この準備で釣る -1ST` でGameへ進む。
6. 成功時は釣果を即時保存し、Result → 町到着で成果を確認する。
7. 町到着から「同じ準備でもう一度」「次の魚を選ぶ」「装備を変える」の順で再出発する。
8. 逃走 / ノーヒット時は既存どおり「同条件で再挑戦」を最短にする。

狙い魚は出現率を変える機能ではない。既存情報を使い、該当する釣り場とヒントを選択・強調するだけの「プレイヤーの目標」とする。

### 3.2 共有する釣行プラン

新しい経済状態ではなく、画面間の選択文脈だけを保持する。

```js
{
  pointId: 'pointA',
  targetFishId: 'aji', // nullable
}
```

- 竿と餌は既存 `ainan_equipment` を正本とし、プランへ複製しない。
- 地点が未解放、魚がその地点にいない、餌が尽きた場合は自動出発せず、既存blockerを表示する。
- `targetFishId` は遭遇抽選や報酬を変更しない。
- 最後に成立したプランだけを保存し、Home、Map、図鑑、装備、町到着から共有する。

### 3.3 情報を詰め込まない表示原則

出発準備カードは全項目の一覧ではなく、判断を一つずつ進めるUIにする。

1. **主情報**: 地点名と狙い魚だけを最初に読む。
2. **主操作**: 出発できる場合は `この準備で釣る -1ST`、できない場合は最優先blockerの解消を一つだけ示す。
3. **準備の要約**: 竿と餌をアイコン付きの2slotで表示する。STは主ボタンの直上に必要量と残量だけ表示する。
4. **補足**: 魚候補、環境、難度、未発見数、ボスは `この釣り場の情報` を開いた時だけ表示する。

同じカード内でも、地点・魚・竿・餌・ST・制約を同じ文字サイズ、同じ色、同じ面積で競合させない。常時見せるのは「何を狙うか」「この準備で出られるか」「次に押す場所」に限定する。

#### スマホ表示の基準

- 375px幅を下限とし、カード左右余白16px、カード内余白16px、主要ブロック間12px、関連要素間8pxを確保する。
- 数値は端末の物理解像度ではなく、実際にレイアウトへ指定するCSS pxを指す。本文と操作ラベルは16〜18pxを基本とし、主ボタンは18px以上、補助情報でも14px未満にしない。地点名などの見出しは20px以上とする。
- 本文line-heightは1.45以上、補助情報は1.4以上。文字を縮小して収めず、情報の優先順位と段階表示で解決する。
- 主ボタンは高さ52px以上、その他のタップ領域も44×44px以上にする。
- 地点名・魚名は初期表示で最大2行まで自然に折り返す。2行を超える場合は省略したままにせず、名称部分のタップ / キーボード選択または隣接する `全文を見る` で、同じsheet内に全文を展開する。閉じると元の2行表示へ戻る。
- 説明文は初期表示を2行までとし、続きは開閉式補足へ移す。操作ラベル、blocker理由、選択中の地点・魚の正式名称は、補足を開けば必ず全文を読めるようにする。
- 操作ラベルとblocker理由には省略記号を使わない。環境タグなど、操作に影響しない補助情報だけ1行省略を許可する。
- 固定高204pxの中へ全情報を押し込まない。カードは内容に応じて伸び、縦長では下部sheet内をスクロール可能にする。主ボタンはsheet下部へ固定する。
- 844×390など横長では、左に主情報、右に準備要約と主ボタンを置く2列を許可する。文字サイズは縦長時から縮小しない。

#### 情報削減の順序

表示が収まらない場合は、次の順に常時表示から外す。フォント縮小は最後の手段にも使わない。

1. ボスの画像と説明
2. 環境、難度、魚影数
3. 魚候補の全件表示（狙い魚 + `ほか3種` に置換）
4. 未発見数と既釣記録

竿・餌は名前と状態だけを常時表示し、性能説明、購入条件、魚種相性はslotを開いた先へ置く。複数blockerがあってもカード上では最優先の一件だけを示し、残りは `ほかの準備不足` にまとめる。

## 4. 画面別仕様

### Home — 今日の起点

- 主目的: 今の状態で次に何をすれば一投へ進めるかを示す。
- 主ボタン: プランが成立済みなら `この準備で出発`、未成立なら `釣り場を選ぶ`。
- 情報優先順位:
  1. 次の釣行プラン（1行目: 場所と狙い魚、2行目: 竿と餌。STは主CTA付近へ分離）
  2. 直近釣果または次の解放条件
  3. ST・ptなどの資源
  4. デイリー、ミッション、免許
- 整理: Growth banner、Guide bubble、Main CTAが同じ目標を重複表示しない。主CTAは一つにする。
- 戻る: 下層画面からHomeへ戻ってもプランを保持する。

### Map地点詳細 — 出発準備の中心

- 主目的: 「どこで、何を狙い、何を持って行くか」を確定する。
- 主ボタン: `この準備で釣る -1ST`。
- 情報優先順位:
  1. 地点名と狙い魚
  2. 出発可否と主ボタン
  3. 装備中の竿、餌と残数、ST
  4. 開閉式の補足内に魚候補、未発見数、環境、難度、ボス
- レイアウト:
  - 上段は地点名、狙い魚、変更ボタンだけにする。
  - 中段は竿 / 餌の2slotと、1行のST表示にする。性能説明は載せない。
  - blockerは主ボタン直上の一件だけ。長文説明や複数警告を並べない。
  - 下段の主ボタンはスクロール中も見失わない。
  - `この釣り場の情報` は初期状態で閉じ、出発操作と視覚的に競合させない。
- 操作:
  - 竿slot / 餌slotを押すと該当tabのUpgradeへ進む。
  - 魚chipを押すと狙い魚を切り替える。
  - 装備変更後は同じ地点詳細へ戻る。
  - blockerがある場合、主ボタンはその解消先を示す。解消後は同じ地点へ戻す。
- キャンセル: 背景タップでカードを閉じる。戻るでHome。どちらもプランを破棄しない。

### Upgrade — 釣行用所持品と見た目

- 主目的: 竿と餌を選び、釣行へ持ち込む状態を確定する。
- 主ボタン: 釣行文脈から来た場合は `この装備で準備へ戻る`。通常入口では既存の装備 / 購入操作。
- 情報優先順位:
  1. CURRENT LOADOUTとキャラクター外観
  2. 選択中アイテムの効果、所持数、装備状態
  3. 購入・補充条件
  4. 素材とWorkshop導線
- 戻る: `returnTo=plan` の場合は元の地点詳細へ、それ以外は既存フッター遷移。
- 境界: 価格、購入量、性能値は変更しない。

### Collection — 次に狙う魚を決める

- 主目的: 記録を確認し、次の釣行目標を選ぶ。
- 主ボタン: 発見済み・未発見ともに詳細内へ `この魚を狙う`。
- 情報優先順位:
  1. 魚名 / 未発見、主な生息地
  2. 釣果数、最大サイズ、BEST
  3. 遭遇ヒント、実績の環境
  4. 図鑑報酬
- 操作: `この魚を狙う` で、その魚が候補に含まれる解放済み地点をMap上で強調する。候補が複数ならMapで選ぶ。
- 戻る: 魚選択前のキャンセルは元画面へ。選択後もHomeへ強制送還せずMapへつなぐ。

### Result — 保存完了を伝える

- 主目的: 一投の結果と、保存された価値を理解させる。
- 成功時主ボタン: `町へ持ち帰る`。補助に既存 `もう一度釣る`。
- 逃走 / ノーヒット時主ボタン: `同条件で再挑戦`。
- 情報優先順位:
  1. 魚 / 成否
  2. サイズ、スコア、初回・記録更新
  3. 得た素材など、今回残ったもの
  4. 次の行き先
- 制約: 背景タップでは遷移しない。明示ボタンだけで進む。

### Town到着 — 成果から次の一投へ

- 主目的: 釣果が町と所持品に残ったことを見せ、次の選択へ橋渡しする。
- 主ボタン: `同じ準備でもう一度`。準備が成立しない場合はblocker解消先を表示。
- 補助導線: `次の魚を選ぶ`、`装備を変える`。
- 情報優先順位:
  1. 今回の魚、サイズ、獲得pt / 素材
  2. 初回、記録、ボス、町の変化
  3. 次の釣行プラン
- 境界: 町施設、魚販売、食事の価格や報酬は変更しない。

### Settings / Save — 安全な復帰

- 主目的: 進行の保護と手動移行。
- 既存: 即時localStorage保存、3世代バックアップ、チェックサム、JSON入出力。
- 追加時の方針:
  - 最後の釣行プランをバックアップ対象に含める。
  - `seen_town`、導線上必要な `seen_*`、daily streakなど、ゲーム進行に影響する既存キーのバックアップ漏れを別途監査する。
  - mid-cast / battleの完全復元はこの最小構成では行わない。

## 5. 戻る・キャンセル・途中再開の契約

| 状況 | 期待動作 |
|---|---|
| Map地点詳細を閉じる | Mapに留まり、選択中プランを保持 |
| 装備変更をキャンセル | 変更前の装備を維持し、元の地点詳細へ戻る |
| 図鑑の魚詳細を閉じる | 図鑑一覧へ戻り、既存プランを変更しない |
| Game開始前に戻る | Mapの同じ地点詳細へ戻る。Gameへ入った後のST扱いは既存仕様を維持 |
| 釣行中にアプリが閉じる | mid-castは復元せず、次回はHomeから最後の成立済みプランを再提示 |
| 釣果表示後にアプリが閉じる | 釣果はすでに保存済み。Homeで直近釣果と同じプランを提示 |
| 餌切れ / ST不足で再挑戦 | 自動消費せずblocker画面へ送り、解消後に元の地点へ戻す |

## 6. 実装優先順

### P0 — 最初に作る: Mapの出発準備カード

既存 `_showPointDetail()` を拡張し、新規sceneは作らない。

- 地点、狙い魚、竿、餌、ST、出発可否を一枚に集約
- 集約は同時露出を意味しない。主情報、準備要約、開閉式補足の3層に分ける
- 竿 / 餌slotからUpgradeへ移動し、同じ地点へ復帰
- 地点と任意の狙い魚を最後のプランとして保持
- 既存 `getFishingPreparation()` のblockerを唯一の出発可否判定にする

Done:

- Home → Map → 装備変更 → 同じ地点 → Gameが迷わず完了する
- 装備変更がない場合、Homeから二操作以内で出発できる
- 未解放、餌切れ、ST不足で誤ってGameへ入らない
- キャンセル / 戻る / 再入場で地点と狙い魚が失われない
- 375px幅で補助14px未満・本文と操作16px未満の文字、44px未満のタップ領域、横スクロールがない
- 長い地点名、魚名、blocker文でも主ボタンが押し出されず、初期2行を超える内容は段階表示へ移り、タップ / キーボード操作で全文を確認できる
- 844×390でも文字を縮小せず、主情報と主ボタンを一画面で確認できる
- 既存の価格、報酬、魚抽選、ST消費量に差分がない

### P1 — 図鑑から狙う

- 魚詳細へ `この魚を狙う`
- Mapで対象地点を強調
- 未発見魚は既存hintだけを使用し、未知情報を開示しすぎない

Done:

- 図鑑 → 魚 → 地点 → 出発が戻り迷子なしで成立
- 対象魚が釣れない地点は開始候補にならない
- `targetFishId` が魚抽選や報酬へ影響しない

### P2 — 釣果から再出発

- Town到着に同条件 / 次の魚 / 装備の三導線
- Homeに直近釣果と現在プランを重複なく表示
- ResultとTownで保存済み内容を同じ語彙で表示

Done:

- 成功 → 町 → 同条件再出発が追加の再選択なしで成立
- 逃走 → 同条件再挑戦は既存の短さを維持
- 釣果、素材、図鑑、魚在庫の表示が保存値と一致

### P3 — 復帰と保存監査

- 最後のプランをsave snapshotへ追加
- 進行に必要な既存キーのバックアップ対象漏れをテストで固定
- 起動、非表示化、JSON import後の復帰先を確認

Done:

- 強制reload後も最後の成立済みプランから再開できる
- 壊れた / 旧versionのプランは安全に破棄され、pointA + 現在装備へfallbackする
- mid-castを「途中再開できる」と誤表示しない

## 7. 実装しないもの

- 新通貨、新ショップ、新しい竿・餌・アクセサリ
- 価格、購入量、報酬、ST、魚の出現率・抽選の調整
- mid-cast / battleの完全なセーブ復元
- 狙い魚を選ぶことで当選率が上がる機能
- 既存のTown、Mission、License、Dailyを統合する大規模メニュー改修

この整理の最初の実装対象は **MapSceneの地点詳細を出発準備カードにすること**。既存データを最も多く再利用でき、Home・図鑑・装備・結果のすべてが戻る中心点になる。
